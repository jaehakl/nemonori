# Nemonori Arcade

게임 목록, 게임 등록·라우팅, 브라우저 세이브 관리를 제공하는 Next.js 프레임워크입니다.
**포켓몬 마블**을 `/games/pokemon-marble`에서 플레이할 수 있습니다.
새 게임을 등록하면 목록과 상세 라우트가 함께 연결됩니다.

## 실행과 검사

Node.js 24 이상과 npm을 사용합니다. 별도 백엔드나 필수 환경 변수는 없습니다.

```bash
npm ci
npm run dev
```

개발 주소는 `http://localhost:3000`입니다. 프로덕션 실행은 `npm run build` 후 `npm start`를 사용합니다.

```bash
npm run check:environment
npm run lint
npm run typecheck
npm test
npm run build
npm audit
```

`typecheck`는 Next 라우트 타입을 먼저 생성합니다. `next-env.d.ts`, `.next`, 로그와 TypeScript 캐시는 자동 생성되며 Git에서 제외됩니다.
CI는 Node 24에서 같은 검사를 실행합니다. 게임 로더와 저장소 테스트에는 Node 내장 테스트 러너를 사용합니다.

## 포켓몬 마블

한 기기에서 1~4명이 조작하는 포켓몬 보드게임입니다. 1인은 AI 없이 포획·육성·도로 점령을
즐기는 탐험 모드이며, 2~4인은 번갈아 대전합니다. 기본 종 1,025종의
한국어 이름·타입·종족값·공격기·진화를 수록하며, 게임 데이터와 이미지가 프로젝트에
포함되어 플레이 중 외부 포켓몬 API를 사용하지 않습니다. 온라인 대전이나 컴퓨터
플레이어는 포함하지 않습니다.

1. 인원과 트레이너 이름을 정하고 시작 포켓몬을 직접 고릅니다. 이전 진화가 없는 일반
   종과 진화하지 않는 일반 종을 선택할 수 있으며 전설·환상은 제외합니다. 한국어·영어
   이름, 도감 번호, 세대와 타입으로 검색합니다. 중복 선택이 가능하고 모두 레벨 5로 시작합니다.
2. 주사위 두 개의 합만큼 40칸 보드를 시계 방향으로 이동합니다. 센터 4칸, 도로 27칸,
   풀숲 9칸으로 이루어져 있습니다. 정확히 도착한 칸에 휴식 중이 아닌 트레이너가 있으면
   순서대로 배틀한 뒤 타일 행동을 진행합니다. 지나치는 트레이너와는 배틀하지 않습니다.
3. 파티가 모두 행동불능이 되거나 자발적으로 센터행을 선택하면 진행 방향 앞의 첫 센터로
   이동합니다. 현재 센터에 있어도 다음 센터로 이동합니다. 자발적 이동은 자기 차례의
   주사위 전이나 칸 행동 완료 후에 선택합니다. 이동한 차례 이후 본인 차례 3번을 쉬며,
   매번 주사위를 굴려 더블이면 파티와 박스를 회복하고 나온 합만큼 즉시 이동합니다.
   탈출 더블에는 추가 굴림이 없습니다. 세 번 모두 실패하면 세 번째 휴식 후 회복하고
   네 번째 본인 차례부터 다시 행동합니다. 휴식 중 트레이너 접촉 배틀·교환은 없습니다.
4. 한 플레이어가 도로 27칸을 모두 소유하면 즉시 승리합니다.
   더블이면 도착 칸 행동을 마친 뒤 다시 굴립니다. 통행료, 화폐와 시간 제한은 없습니다.

| 타일 | 행동 |
| --- | --- |
| 풀숲 | 행동 가능한 파티의 최고 레벨보다 0~2 낮게 상한을 정한 기본형 야생과 배틀합니다. 내 공격 대신 포켓볼을 던질 수 있으며, 성공하면 남은 HP로 합류합니다. 파티 6칸이 차면 포획할 수 없습니다. |
| 포켓몬센터 | 파티와 박스를 전부 회복하고 교환합니다. 박스는 센터에서만 이용하며, 박스에 들어가는 포켓몬은 항상 완전히 회복합니다. 도로 수비는 센터에서 회복하지 않습니다. |
| 도로 | 살아 있는 파티 포켓몬을 배치합니다. 수비 성공 시 승리 경험치를 받고 배틀 종료 후 완전 회복합니다. 패배한 수비는 박스로 돌아가 완전히 회복합니다. 내 도로에서는 유지·회수·교체할 수 있으며, 회수에는 파티의 빈칸이 필요합니다. |

배치·교체 후에도 파티에 살아 있는 포켓몬이 최소 한 마리 남아야 합니다.
풀숲 위치는 3·8·13·19·23·29·33·36·39번 칸입니다.
휴식 중에도 소유 도로와 수비는 유지됩니다. 상대는 수비에 도전할 수 있고,
수비의 패배나 회수로 빈 도로가 됩니다. 휴식 종료 시 배치 중인 수비는 회복하지 않습니다.

### 배틀과 성장

- 이동 중인 활성 플레이어는 후공입니다. 상대가 먼저 출전 포켓몬을 선택하고 공격합니다.
  각자 한 마리만 출전하며 배틀 중 교체·도주는 없습니다. 다른 사람의 수비 포켓몬도
  그 소유자가 기술을 선택하고, 야생만 자동 공격합니다.
- 물리·특수 공격과 방어, 기술 위력, 자속 1.5배, 복합 타입 상성을 적용합니다.
  버튼의 예상 피해는 명중했을 때 방어·자속·상성까지 적용한 값이며 급소는 제외합니다.
  ‘계산 상세’에서 계산식을, ‘배틀 기록’에서 직전 행동의 실제 HP 감소·회복·반동을 확인합니다.
  명중률, 급소(기본 1/24, 피해 1.5배), 흡수·반동, 연속 타격, 충전·휴식,
  상태이상과 능력치 변화를 적용합니다. 상태와 능력치 변화는 배틀 종료 시 해제하고 HP는 유지합니다.
  양쪽 행동 이후 지속 피해를 처리합니다. 스피드·우선도로 순서를 바꾸지 않으며 PP 제한은 없습니다.
- 처음에는 현재 레벨에서 배울 수 있는 공격기 중 서로 다른 타입을 우선하여 위력 순으로
  최대 세 개를 편성합니다. 고정 피해 기술은 숫자 위력 기술 뒤에 ID순으로 편성합니다.
  이후 보유 기술은 저장하며 레벨업·진화 때 자동으로 교체하지 않습니다. 새 기술은 빈 슬롯에
  추가하고, 세 칸이 차 있으면 기존 기술과 새 기술의 타입·분류·위력·명중률·효과를 비교해
  교체하거나 배우지 않을 수 있습니다. 여러 레벨이 오르면 습득 레벨순, 같은 레벨이면
  기술 ID순으로 제안하며, 진화형에서 새로 열린 기술도 포함합니다. 기존 기술은 진화 후에도 유지합니다.
  사용할 수 있는 기술이 없을 때만 발버둥(무상성 물리 위력 50, 최대 HP의 1/4 반동)을 제공합니다.
  도구·날씨·필드·특성·교체·별도 폼은 지원하지 않으며, 필수 조건이 없는 기술은 기본 효과로 사용합니다.
  반동이나 라운드 종료 피해로 동시에 쓰러지면 무승부이며 경험치와 즉시 도로 배치는 없습니다.
  쓰러진 도로 수비는 박스에서 회복하고 해당 도로는 비워집니다.
- 경험치 1,000마다 1레벨 상승하며 남은 경험치를 이월합니다. 동일 레벨 승리 보상은
  레벨 1에서 5,000(500%), 15에서 2,000(200%), 30에서 1,000(100%), 50에서 500(50%)이며,
  100레벨 기준점 250까지 선형 보간합니다. 상대/내 레벨 비율을 0.1~2배로 제한해 보정하고
  정수로 반올림합니다. 최대 100레벨에서는 추가 경험치를 쌓지 않습니다.
- 일반 레벨 진화는 원래 요구 레벨을 유지하고 특수 조건은 레벨 20으로 대체합니다.
  여러 진화 조건을 충족하면 순서대로 진화하며 분기는 직접 고릅니다. 레벨업·진화로 HP를 회복하지 않습니다.
- 40번→1번 칸으로 한 바퀴를 완주하면 해당 플레이어의 파티와 도로 수비 각각에게
  동일 레벨 승리 경험치를 지급합니다. 행동불능도 포함하고 박스는 제외합니다.
  강제·자발적 센터 이동은 완주로 세지 않습니다. 기술 습득과 분기 진화를 차례로 선택한 뒤 남은 이동을 재개합니다.
- 포켓볼은 무제한이며 내 공격 차례를 소모합니다. 성공 확률은
  `min(95%, 25% + 65% × (1 − 야생 현재 HP / 최대 HP) + 1%p × max(0, 출전 포켓몬 레벨 − 야생 레벨))`입니다.
  체력이 낮거나 출전 포켓몬의 레벨이 높을수록 쉽게 잡히며, 내 레벨이 낮아도 확률은 차감하지 않습니다.
  야생이 풀 HP일 때 레벨차 +5는 30%, +10은 35%, +20은 45%이며 최대 95%입니다. 실패하면 야생이 공격하며,
  성공하면 출전 포켓몬이 승리 경험치를 받습니다. 쓰러진 야생과 상대 트레이너의 포켓몬은 포획할 수 없습니다.
- 야생은 이전 진화가 없는 종만 출현하며, 진화하지 않는 종도 포함합니다. 등장 비중은
  일반 기본종 90%, 종족값 합계 500 이상 일반 기본종 9%, 전설·환상 기본종 1%입니다.
  범주는 중복되지 않으며 야생 레벨은 내 파티에서 HP가 남아 있는 포켓몬만 기준으로 정합니다.
  최고 레벨에서 0·1·2 중 하나를 균등 추첨해 뺀 값(최소 1)을 상한으로 정하고,
  최저 레벨과 상한 중 작은 값을 하한으로 삼아 하한~상한에서 양 끝을 포함해 균등 추첨합니다.
  레벨 5 스타팅 한 마리이면 야생은 3~5, 파티가 레벨 5·12이면 5~무작위 상한(10~12)입니다.
  행동불능·박스·도로 수비 포켓몬은 범위에서 제외합니다. 기존 저장의 포켓몬 레벨과 진행 중인
  야생전은 유지하며, 변경된 야생 레벨 규칙은 새 조우부터 적용합니다.

40칸 보드와 배틀 경기장은 확대해도 선명한 평면 SVG로 표시합니다.
WebGL 컨텍스트를 만들지 않아 배틀을 반복해도 그래픽 가속 초기화나 복구가 필요하지 않습니다.
말은 파티 최고 레벨 포켓몬 그림에 플레이어 고유색 테두리를 두릅니다. 동률이면 파티의 기존 순서를
따르고 행동불능도 포함합니다. 카드도 레벨 내림차순이며 원본 보관 순서는 유지합니다. 도로 수비 그림과
최대 네 개의 말은 서로 다른 영역에 배치하고, 포켓몬 이미지의 투명 여백을 보정합니다.
주사위는 1.8초 동안 흔들림·구르기·감속·착지를 표현하고, 두 주사위의 위치와 충돌에 맞춘
스테레오 효과음을 합성합니다. 이동 중에는 중앙 패널과 파티 카드의 배치를 유지합니다.
이동·18타입 공격·쓰러짐·회복·포획·진화·우승도 짧은 연출과 효과음으로
표현합니다. 기존 포켓몬 PNG와 투명 여백 보정 캐시를 보드·배틀에서 공유하며,
이미지 실패 시 이름과 색상으로 대체합니다. 체력과 피해는 선명한 HTML로 표시합니다.

iPad Pro 12.9형 2세대의 iPadOS 17 Safari 가로 화면을 기준으로 설계했습니다.
주요 조작 영역은 48px 이상이며, 현재 턴 플레이어의 파티만 144px 그림의 트레이딩 카드로
표시합니다. 보드 중앙에서 카드를 가로로 넘겨 보고 주요 행동 버튼을 누릅니다.
시스템 버튼은 보드 좌우 여백의 작은 아이콘으로 표시하며 터치 영역은 48px을 유지합니다.
세로 화면과 숨김 탭에서는
연출·자동 진행·소리가 멈추며, 복귀하면 남은 시간부터 이어집니다.
스마트폰 전용 화면은 제공하지 않습니다. 일반 버튼과 선택 입력은 키보드로도 조작합니다.

시작 화면에서 각 트레이너의 자리(아래·왼쪽·위·오른쪽)를 정합니다. **화면·사운드**에서
고정 방향(기본값)과 조작자 방향 자동 회전을 선택합니다. 자동 모드는 실제 입력자를 따라
중앙 카드·조작 패널만 회전하고 보드는 고정합니다. 배틀에서는 조작자 쪽의 작은 팝업 모달에
체력·기술 선택을 표시하고 포켓몬이 가려지지 않도록 무대 공간을 확보합니다. 연출 중에는 방향을 유지하며
야생의 자동 공격은 현재 턴 플레이어 방향을 따릅니다. 화면 모드는 게임 저장과 별도로 보존합니다.

같은 설정에서 전체 음소거, BGM·효과음 볼륨, 동작 줄이기를 조절합니다.
**전체 화면** 버튼으로 게임 영역을 화면에 채우거나 원래 크기로 돌아옵니다.
전체화면에서는 보드가 화면의 짧은 변을 채웁니다.
iPadOS 16.4 이상 Safari의 표준 Fullscreen API를 사용하며, 시스템 제스처나 Esc로
종료해도 버튼 상태가 동기화됩니다. 미지원 브라우저에서는 버튼을 비활성화합니다.
지원 범위는 [WebKit의 Safari 16.4 안내](https://webkit.org/blog/13966/webkit-features-in-safari-16-4/)를 따릅니다.
배경음악은 제공된 포켓몬 음악 10곡을 AAC-LC로 압축한 파일이며, 필요한 곡만 같은
사이트에서 불러옵니다. 효과음은 기존 Web Audio 합성을 유지합니다. 게임 영역의 첫
클릭·터치·키 입력이나 시작·이어하기·소리 재생 버튼에서 오디오를 활성화합니다. Safari 복귀 후
소리가 없으면 **소리 재생·다시 연결**을 누릅니다. 기본 볼륨은 음악 30%, 효과음 60%이며,

복귀합니다. 탭 숨김·세로 방향·음소거·음악 볼륨 0에서는 음악을 일시정지합니다.

`public/pokemon-marble/bgm/`에 있습니다. FFmpeg가 설치된 환경에서
`npm run encode:pokemon-bgm`으로 64kbps, 44.1kHz 스테레오 AAC-LC 파일을 다시 생성합니다.
필요하면 `FFMPEG_PATH`로 실행 파일을 지정하고, 변환 스크립트의 `bitrateOverrides`에
곡별 `80k` 설정을 추가할 수 있습니다. 앨범 이미지·메타데이터를 제외하고 faststart를
적용합니다. 생성한 파일을 저장소에 포함하므로 일반 빌드에는 FFmpeg가 필요하지 않습니다.

진행 상황은 확정 행동마다 공통 저장 API에 자동 저장합니다. 시작 화면의 이어하기는
주사위, 이동 잔여 거리, 진행 중 배틀, 진화 선택과 난수 상태를 복원합니다.
게임 내부 저장은 v5이며 경험치, 배틀 결과, 최초 스타팅, 자리 방향과 남은 휴식 횟수를 보존합니다.
포켓몬별 보유 기술, 습득 대기 목록, 탈출 주사위 여부도 저장합니다. 기술 선택이나 휴식 중
이어하기를 해도 경험치·포획·이동을 중복 처리하지 않습니다.
충전·휴식·상태이상·능력치 단계·지연 공격과 직전 행동의 계산 기록도 저장합니다.
정상 v2·v3·v4는 기존 HP·진행·난수를 보존해 이전합니다. v2·v3의 전투 임시 상태는 초기화하고
v4의 진행 중 전투는 보존합니다. 이전 보드의 센터·풀숲·도로를 각각 순서대로 새 보드의 같은
종류 칸에 대응시켜 플레이어와 수비의 위치를 함께 옮깁니다. 위치 번호가 달라질 수 있으며 로그로 안내합니다.
기존 포켓몬과 지연 공격 스냅샷의 기술은 이전 편성 결과로 초기화하며 과거 습득 선택은 다시 묻지 않습니다.
v2의 XP는 0으로 변환하며, 다음 확정 행동에서 저장합니다. 과거 일반공격 기록은 읽기만 허용합니다.
이미 받은 성장 보상은 다시 지급하지 않습니다. 이전 포획 대기만 기존 HP 0 포획으로 완료할 수 있으며,
저장된 진화형 야생 전투도 계속할 수 있습니다. 새 야생 전투에는 새 포획·출현 규칙을 적용합니다.
구버전 v1은 자동 삭제하거나 변환하지 않습니다. 호환 안내 후 새 모험을 시작할 때만
기존 확인 절차를 거쳐 저장을 교체합니다. 공통 저장 프로토콜은 변경하지 않습니다.
저장 실패와 손상 데이터는 화면에 별도로 안내하며 같은 브라우저의 `/saves`에서 관리합니다.

### 연출 구조와 성능 검수

`transitionWithEvents`는 기존 규칙 처리 결과와 사건별 독립 스냅샷을 반환합니다.
`transition`은 같은 엔진에서 상태만 반환하므로 버튼 검증과 실제 행동의 규칙이
일치합니다. 확정 상태를 먼저 저장한 뒤 연출 큐가 화면과 소리를 재생합니다.
연출 큐는 게임 RNG를 사용하지 않으며, 스킵은 표시만 종료합니다. 이미 저장한 행동을
다시 실행하지 않습니다. 이어하기는 과거 효과를 재생하지 않습니다.

배틀은 고정된 SVG 경기장과 두 포켓몬, 공격 시 최대 9개의 타입별 도형으로 구성합니다.
등장·공격·피격·기절·포획·진화는 기존 연출 진행률에서 직접 계산하며 별도 타이머를
만들지 않습니다. 체력과 타격 효과는 진행률 45%에서 함께 반영합니다.
일시정지는 현재 그림을 유지하고 건너뛰기는 효과를 즉시 종료합니다.
동작 줄이기에서는 이동·흔들림 대신 고정된 타격 표시와 투명도 변화를 사용합니다.

**30fps는 구현 목표이며 대상 아이패드의 실측 결과가 아닙니다.** 출시 전 실기기에서
10분 이상 플레이와 배틀 20회를 반복하고 다음을 확인합니다.

- 공격 전후 HP와 소리의 일치, 마지막 일격·진화·포획·우승 순서
- 연출 스킵·빠른 연타·세로 전환 후 복귀 시 중복 행동 없음
- 화면 잠금·탭 전환 후 조작과 소리 복구, 음소거·개별 볼륨
- 화면 잘림과 작은 터치 영역 없음, 지속적인 프레임 저하나 자원 누수 없음
- 배틀 20회 이상 반복 후에도 무대 표시, 저장 재개와 앱 전환 후 복귀 유지

데스크톱의 아이패드 화면 크기 검증은 실기기 Safari 성능 검수를 대체하지 않습니다.

## 새 게임 등록

1. 클라이언트 React 컴포넌트를 만들고 default export합니다. 게임별 스타일은 인접한 CSS Module에 둡니다.
2. `app/games/data.ts`의 `defineGameCatalog` 배열에 메타데이터와 literal 동적 import를 함께 등록합니다.

```tsx
export const gameCatalog = defineGameCatalog([
  {
    slug: "new-game",
    title: "새 게임",
    summary: "게임 설명",
    tags: ["puzzle"],
    difficulty: "Easy",
    estPlayMinutes: 5,
    accent: "#0f766e",
    load: () => import("./_components/new-game/NewGame"),
  },
]);
```

slug는 소문자 영문·숫자와 단어 사이의 하이픈만 사용하며 중복을 허용하지 않습니다.
메타데이터와 구현을 별도로 매핑하지 않습니다. 등록부와 서버 렌더링은 게임 모듈을 실행하지 않습니다.
GameHost는 마운트 후 로더를 호출하므로 서버와 브라우저의 첫 화면이 같은 로딩 상태로 시작합니다.

## 저장 계약

- 프로토콜: `nemonori.save.v1`
- 키: `nemonori.arcade:game:{slug}:save`
- Envelope: `protocol`, `gameSlug`, `gameTitle`, `updatedAt`, `data`
- 기존 브라우저 세이브는 게임 삭제 후에도 보관됩니다. 등록되지 않은 게임의 실행 링크는 표시하지 않습니다.

저장 API는 성공 시 `{ ok: true, value }`, 실패 시 `{ ok: false, error, partial? }`를 반환합니다.
오류 코드는 `storage-unavailable`, `quota-exceeded`, `invalid-data`, `storage-error`입니다.
조회 실패와 빈 목록을 구분하고, 일괄 삭제 실패에는 이미 삭제된 키와 실패한 키를 `partial`로 제공합니다.

게임 코드는 직접 `localStorage.setItem`을 호출하지 않고 공통 유틸을 사용합니다.
게임 데이터는 유한한 숫자, 문자열, boolean, null, 배열, 일반 객체로 구성합니다.
함수, undefined, BigInt, 날짜 객체, 순환 참조 등 JSON에서 손실되는 값은 거부합니다.
수정 가능한 객체를 저장해도 반환되는 Envelope는 저장 당시의 독립된 스냅샷입니다.

```ts
import { loadGameSave, saveGameSave } from "@/app/lib/save-protocol";

type SaveData = { version: 1; bestScore: number };

function isSaveData(value: unknown): value is SaveData {
  return value !== null && typeof value === "object"
    && "version" in value && value.version === 1
    && "bestScore" in value && typeof value.bestScore === "number"
    && Number.isFinite(value.bestScore);
}

// 호출은 클라이언트 마운트 후에 수행합니다.
const loaded = loadGameSave("new-game", isSaveData);
if (!loaded.ok) {
  // loaded.error.message를 사용자에게 표시합니다.
} else if (loaded.value) {
  // loaded.value.data는 검증된 SaveData입니다.
}

const saved = saveGameSave("new-game", "새 게임", { version: 1, bestScore: 100 });
if (!saved.ok) {
  // 저장 실패를 표시합니다. 성공했다고 안내하거나 기존 데이터를 지우지 않습니다.
}
```

검증함수가 없는 로드는 `unknown` 데이터를 반환합니다. 타입을 지정하려면 검증함수를 전달해야 합니다.
게임별 데이터 버전과 이관은 해당 게임이 소유하고, 공통 Envelope와 키는 유지합니다.
손상된 세이브는 읽기만으로 변경하지 않습니다. `/saves`에서 원본 확인과 명시적 삭제를 지원합니다.
삭제는 실제 저장 키를 기준으로 하며 다른 앱의 데이터는 보존합니다. 전체 삭제는 확인 후 실행합니다.

React 화면에서는 `useGameSaves`를 사용합니다. 이 훅은 고정된 서버 로딩 스냅샷으로 hydration을 시작하고,
같은 탭의 저장·삭제와 다른 탭의 storage 이벤트를 반영합니다. 직접 저장소를 수정한 외부 도구의 결과는 새로고침으로 반영합니다.

## 게임의 수명주기

- 브라우저 엔진, 오디오, worker 등은 effect에서 초기화합니다. 모듈 최상위에서 window나 엔진을 실행하지 않습니다.
- 비동기 초기화는 페이지 이탈·재시작을 확인하고, 취소되거나 일부 초기화가 실패하면 생성된 자원도 정리합니다.
- cleanup에서 timer, listener, engine, AudioContext, worker를 해제합니다. 정리 과정에서 새 자원을 생성하지 않습니다.
- 상태 updater는 순수하게 유지합니다. 보상 지급이나 다른 상태 변경을 updater 안에서 실행하지 않습니다.
- 타이머는 표시용 상태 변경 때문에 재시작되지 않도록 설계합니다.
- GameHost는 import 실패와 React 렌더 오류를 처리합니다. 게임 내부의 비동기 오류와 이벤트 처리 오류는 게임이 처리해야 합니다.

## 환경 파일과 인코딩

실제 환경 값은 로컬 `.env.local` 또는 배포 환경에서 관리합니다. `.env.example`에는 주석과 빈 값만 넣습니다.
`npm run check:environment`와 CI는 환경 파일이 Git에 추적되거나 예제에 값이 들어가면 실패합니다.
검사 출력에는 파일 이름만 사용합니다. 환경 값, 설정 객체, 비밀값이 포함된 diff를 로그에 출력하지 않습니다.

모든 소스와 문서는 BOM 없는 UTF-8로 저장합니다. Git의 텍스트 규칙은 소스 파일의 LF 줄바꿈을 유지합니다.
자격 증명 이력 정리 후 다른 작업본은 새로 clone하거나 정리된 이력으로 재구성해야 합니다.
기존 작업본의 옛 이력을 merge하여 다시 게시하면 삭제했던 자격 증명 이력이 복원될 수 있습니다.
